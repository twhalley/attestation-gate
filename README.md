# attestation-gate

[![Open in GitHub Codespaces](https://github.com/codespaces/badge.svg)](https://codespaces.new/twhalley/attestation-gate)

A Kubernetes admission gate that only runs container images signed and attested
by one specific GitHub Actions workflow — and **a test suite that proves it
rejects everything else**.

Plenty of repositories demonstrate `cosign sign`. The interesting part is not
the happy path. It is whether the control fails closed when someone tries to get
around it, so this repository is built around four deliberate bypass attempts
and asserts that each one is refused.

```
┌──────────────────────┐   sign + attest (keyless, Fulcio + Rekor)
│ build-sign-attest.yml│ ─────────────────────────────────────────┐
└──────────────────────┘                                          │
┌──────────────────────┐   signs correctly, wrong identity        ▼
│ untrusted-signer.yml │ ──────────────────────────────────► ghcr.io/…/app
└──────────────────────┘                                          │
┌──────────────────────┐                                          ▼
│      gate.yml        │  kind + sigstore/policy-controller ── admit / reject
└──────────────────────┘
```

## The test suite

| Case | Image state | Expected | What it proves |
|---|---|---|---|
| `trusted` | Signed + SLSA provenance, release workflow | **admit** | The happy path works and the pod actually runs |
| `unsigned` | No signature | **reject** | The gate is on |
| `no-provenance` | Correctly signed, no attestation | **reject** | A signature alone is not enough |
| `rogue` | Validly signed *and* attested by a different workflow in the same repo | **reject** | Trust is pinned to an identity, not to "is it signed?" |
| `keysigned` | Real signature, never written to the transparency log | **reject** | Signing cannot happen off the record |

`rogue` is the case worth reading. It is signed correctly, attested correctly,
and its Rekor entry is genuine. It is rejected because Fulcio binds the
certificate to the workflow that requested it, and the policy names one workflow.

Results are regenerated on every push to `main` — see the job summary of the
[`gate`](../../actions/workflows/gate.yml) workflow.

## Two controls, deliberately layered

The `gated` namespace enforces Pod Security Admission (`restricted`) alongside
the signature policy. They answer different questions:

| | Question | Control |
|---|---|---|
| Provenance | Where did this image come from? | `policy.sigstore.dev` |
| Posture | What can it do once it is running? | Pod Security Admission |

Neither substitutes for the other — a perfectly signed image still runs as root
if nothing stops it, and a beautifully confined pod is still whatever an
attacker managed to push.

Layering them creates a subtle test-design problem, which is worth knowing
about: PSA runs first, so a test pod that fails PSA is rejected before the
signature webhook is consulted, and every negative case passes while proving
nothing. `test/run.sh` therefore gives every pod a `restricted`-compliant
`securityContext` — holding posture constant so provenance is the only
variable — and asserts on *which* controller rejected it.

The hardened image is built to satisfy `restricted` unmodified: UID 65532,
read-only root filesystem, all capabilities dropped, `no-new-privileges`.

## Base image comparison

`scan-diff` builds the same Flask application, with the same pinned
dependencies, on `python:3.12` and on `cgr.dev/chainguard/python`, then reports
CVE counts, SBOM package counts and image size for both. Generated by
[`scripts/scan-diff.sh`](scripts/scan-diff.sh) on every pull request and posted
as a comment, rather than written into this README once and left to rot.

Snapshot from a local run on 2026-08-02 — treat the workflow output as
authoritative rather than this table:

| Metric | Baseline (`python:3.12`) | Hardened (`cgr.dev/chainguard/python`) |
|---|---:|---:|
| Critical CVEs | 91 | 0 |
| High CVEs | 360 | 0 |
| **Total CVEs** | **1972** | **4** |
| Packages in SBOM | 488 | 41 |
| Image size | 1.1 GB | 83 MB |

**The four remaining CVEs are the interesting part.** Two are in CPython
itself and two are in Flask — the interpreter this application requires and a
dependency it chose. Not one is in the base OS, because there is no base OS
left. That is the honest shape of the result: a minimal base image removes the
distribution you never asked for, and cannot remove the software you did.

Python makes this clearer than a compiled language would. A static Go binary on
`chainguard/static` scans as a clean zero, which flatters the base image and
hides the point. See [`vex/`](vex/) for the next question — what to do about a
CVE that is present but not reachable.

## Try it

Click the Codespaces badge above — the devcontainer installs podman, cosign,
kind, kubectl, helm, syft, grype and jq, and takes about three minutes. Or
locally, with those on your `PATH`:

```bash
./scripts/scan-diff.sh   # build both images, compare CVEs, packages, size
./test/setup.sh          # kind cluster + policy-controller + policies
./test/run.sh            # the five admission cases
```

`make help` lists the shortcuts. `scan-diff.sh` works standalone; `run.sh`
needs images in GHCR, so it only passes once the pipeline has run.

Images are built with **podman** — rootless and daemonless, so no build step
holds a socket equivalent to host root. That applies in CI too: the workflows
use `podman build` and `podman push --digestfile` rather than the Docker
daemon. `kind` is the one exception and still runs on Docker, because its
podman provider is experimental and the cluster runtime is not the
supply-chain-relevant part.

### One-time setup if you fork this

1. Replace `twhalley/attestation-gate` in `policy/*.yaml` and the workflow `env:`
   blocks with your own repository — the policy pins a workflow identity, so it
   will reject your builds until you do.
2. Make the GHCR package public (Packages → attestation-gate/app → Package
   settings → Change visibility). Admission tests pass either way, but the
   admitted pod cannot pull a private image without an `imagePullSecret`.

## Deliberate omissions

- **No CVE threshold in admission.** Blocking on severity counts without
  reachability analysis produces alert fatigue and pressure to add exceptions.
  `scan-diff` measures; it does not enforce.
- **No SLSA L3 claim.** Provenance is generated by the same job that builds the
  artefact, so it is authenticated but falsifiable. Reaching L3 means an
  isolated builder. See THREATMODEL.md.
- **One cluster, one namespace.** Multi-tenant enforcement and namespace-label
  governance are named as gaps rather than half-implemented.

Infrastructure-as-code, EKS and GitOps are not repeated here — they are in
[payments-platform-poc](https://github.com/twhalley/payments-platform-poc).
This repository is deliberately about one control, done properly.
